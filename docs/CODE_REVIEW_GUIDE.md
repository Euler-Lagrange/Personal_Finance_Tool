## Test and review workflow

Use the commands in [the root README](../README.md) and [section workflow](DEVELOPMENT_WORKFLOW.md). The first Rust build after cleanup will rebuild its cache. Run Cargo commands sequentially. Use temporary synthetic databases and mock provider transports; do not open, migrate, restore or delete Jacob's real app data for QA. Do not automatically send the reference images to a model API.

Begin with [the final lifecycle test](../src-tauri/src/tests/final_lifecycle.rs), then inspect its assumptions rather than merely rerunning it. Follow the requirement-specific tests in the traceability matrix. Check migrations and corrupt-restore paths for each invariant. Exercise rejection and valid acceptance, repeated operations, failed writes, later corrections and closed-period effects.

## Requested review output

Provide findings in severity order, each with a requirement/screenshot/decision ID, source path and symbol, a concrete failing scenario, expected versus actual behavior, and a proposed regression test. Distinguish reproduced defects, strong code-based hypotheses, missing requirements, external verification gaps and optional improvements. Include what you checked and what remains unverified. Challenge design decisions when they conflict with Jacob's stated workflow; do not assume the current architecture is the only acceptable solution.
