# Requirements → design → code → evidence

Updated November 4, 2026. This is an implementation map, not a substitute for [the full requirements](REQUIREMENTS.md). IDs R01–R29 identify user needs; D01–D16 refer to [design decisions](DESIGN_DECISIONS.md); S1–S6 refer to [the original screenshots](reference/SCREENSHOTS.md). G01–G10 refer to limits/findings in [the code review guide](CODE_REVIEW_GUIDE.md).

**Status language:** Implemented means the named code path exists and has recorded synthetic coverage. Limited means the target is only partly covered or narrower than the user's desired experience. Deferred means explicitly follow-on scope. External means actual Windows/device/issuer/provider acceptance is still needed. A test link is a place to inspect evidence, not a claim that every path is covered.

## Scope rules for reviewers

Treat screenshot conveniences such as per-day cost and salary-derived rent ratios as references unless a confirmed answer requires them. Treat manual control, actual spending, 70/30 with overrides, bills, annual close, reliable imports, screenshot intake, provider choice, and laptop portability as substantive needs. The low-review burden is a user goal even where the current implementation is conservative. Any discovered omission should remain visible as an omission; passing synthetic cases must not redefine the requirement.
