# QA/QC pass — November 3, 2026

The current manual-entry and setup preview passed this QA pass after four defects were reproduced and fixed. The scope was financial correctness, workspace isolation, save/error handling, database upgrades and recovery, and the existing browser UI suite. This is a checkpoint for continuing development, not certification of the complete planned finance product.

## Findings and corrections

| Finding | Reproduction | Correction and verification |
| --- | --- | --- |
| Backup restore accepted unusable or inconsistent databases | Remove a required table/column, or alter/delete account activity in an otherwise readable SQLite backup. Restore previously accepted it and could replace valid live data. | Copy to an isolated candidate before validating it; check required tables/columns, references, account effects, household deltas, and expense allocations before replacement. Regression tests cover missing budget/audit data, missing category icons, missing/wrong activity, wrong account references, wrong shared balances, and inconsistent split settings. Invalid candidates leave live records intact. |
| Old PayPal repayments could not be edited after the household balance reversed | Record a $30 Chelsea repayment, then a later Chelsea-paid purchase that makes Jacob owe her. Adding checking as the destination of the original receipt was rejected. | Edits that preserve the repayment's amount and payer do not settle the debt again. Cash-out/account/note edits now work; changed amounts and new repayments still undergo the debt limit check. The test verifies no duplicate income, spending, or settlement. |
| A late operation could display the previous workspace under the new workspace label | Start a sample-workspace backup, switch to personal before it completes, then let the old operation refresh. | Refreshes are scoped to both the selected workspace/month and their request order. A delayed-operation UI test verifies the personal workspace keeps its own data. |
| A successful write could be presented as a failed save | Let a save succeed, then fail its follow-up snapshot request. The form remained open with its old revision. | Successful writes close their forms. A refresh failure explicitly says the change was saved and offers a read-only retry. A UI test verifies retry does not submit the entry again. |

All three new defect-focused Rust tests and both new UI tests were observed failing before their fixes. A fourth Rust test checks that stricter recovery validation still accepts valid income, savings-account spending, PayPal holdings, and repayments in both directions. Existing version 1 migration and backup-restore tests remain passing.

## Verification

- `cargo test --manifest-path src-tauri/Cargo.toml`: **23 passed**, including real SQLite operations in temporary directories, restart, migration rollback, backup retention, and restoration.
- `npx playwright test`: **24 passed** in one full run, using synthetic records and mocked native commands. Covers twelve themes, representative contrast checks, compact layouts, keyboard theme selection, entry forms, setup, archiving, budgets, validation errors, and the new asynchronous failure cases.
- `cargo clippy --manifest-path src-tauri/Cargo.toml --all-targets -- -D warnings`: passed. The environment emitted incremental-cache hard-link warnings and used file copying; no Clippy findings.
- TypeScript/Vite production build, Prettier check, and Rust formatting check: passed.
- `npm run build:desktop`: passed. Delivered as `builds/Personal Finance Preview - QA.exe`; SHA-256 of the copy matches the compiled release executable.

The user's actual financial databases were not opened, modified, migrated, or restored during this pass. No financial records were sent to an external service. The source review found local UI assets and a production connection policy limited to the native IPC bridge; this was not a network packet audit.

## Remaining limits

- Browser checks exercise a mocked native-command boundary. Rust tests exercise the real database separately. This pass does not prove end-to-end interaction through the packaged Windows WebView. Native UI automation was previously unavailable because of a Computer Use approval timeout; it was not retried in this pass. A hands-on Windows smoke test remains useful before relying on the preview for real records.
- The preview still lacks imports, refunds, transfers/card payments, bills, goals, month close, annual reports, and portable encrypted transfer. Accounts show recorded activity rather than reconciled balances.
- This is not a comprehensive security/accessibility audit, an installer test, a disk-failure simulation, or a second-device test. Local recovery retains the newest 20 copies and is not an off-device backup.

The next development slice remains transfers and credit card payments, followed by a Capital One importer using representative exports. Preserve these regression tests as that work changes accounting and recovery behavior.
