# Encrypted laptop handoff - November 4, 2026

Schema 35 adds complete passphrase-encrypted workspace exports and reviewed replacement imports. Records, embedded documents, configuration and history travel together. API keys/provider settings and appearance remain device-local. This is a manual handoff between computers, with no automatic merge or synchronization. The UI supports browsing and dropping a handoff file, conflict review, renewed approval after edits, retained operation IDs after lost replies, and closing a completed import before refreshing.

Native checks compare actual canonical content against immutable shared ancestry. Equal entry counts do not hide divergent changes. Unrelated, older and diverged replacement needs an extra acknowledgement. Every import preserves the prior local database in a `.handoff.sqlite` recovery point excluded from ordinary rotation, then activates a validated immutable candidate with an atomic SQLite backup replacement. The portable file is encrypted; live databases and preserved recovery copies retain Windows/device protection. OS-held locks prevent competing windows and workspace operations. Active AI requests block handoff.

Findings and fixes:

- Initial round trips failed because SQLite serialization retained WAL file-header flags. Normalize the standalone snapshot to rollback format before hashing/encryption, following SQLite's documented deserialization guidance. All two-store round trips now pass.
- Export retries initially trusted any existing output at the generated path. They now decrypt/authenticate it and compare its transfer identity, label, lineage and node before returning success. Corruption and changed details reject without overwriting the file.
- Mixed handoff/transaction drops initially reported an error only on the Imports screen. User input errors now appear on the current screen. The first full browser pass exposed unrelated native-drop availability notices competing with form alerts; those passive notices remain in Imports. The corrected full suite passes.
- The first fault fixture used `PRAGMA query_only`, which does not prevent SQLite's backup API from replacing the database. A true read-only destination connection now reproduces replacement failure and confirms local records survive. Synthetic month-close fixtures use a completed month, and test selectors match actual UI labels.
- Clippy required moving helper functions before test modules. No behavior changed.
- Compilation exhausted disk space while generating unused static/C ABI app libraries. Removed only verified generated debug artifacts, and limited this Windows-only crate to its used Rust library output. Delivered builds and user data were not removed.

Validation: full baseline **333 core passed, 2 explicitly ignored environment tests**; **186 mocked browser passed**. Seven handoff integration cases cover complete evidence/close/accounting round trips, ancestry and equal-count conflicts, confirmation/staleness/retries, read-only replacement failure, preserved-copy rotation/restore, wrong passwords/tampering/truncation/workspace/schema/trigger rejection, invalid money/active requests, and schema-34 upgrade. Separate tests exercise OS leases and the production encryption work factor. Faster synthetic handoff fixtures use a lower test-only work factor; production exports always use 18. Final focused checks also verify exact source bytes and application-lock release. TypeScript, Prettier, Rustfmt and Clippy with warnings denied pass. Compact light/dark review and confirmation screenshots were visually inspected at 1100 x 780.

Windows release/copy verification passed. Packaging and final synthetic integration follow this checkpoint. No live financial records or provider requests were used. Native WebView file-picker/drop, actual second-device transfer, installation and real issuer/provider behavior remain unverified. Cryptographic library use and these tests do not constitute an independent security audit. Limits: 256 MiB database, 258 MiB encrypted input, 4,096 transfer nodes; retained handoff copies consume local disk.
