# Import identity and coverage implementation

This extends the approved matching requirements; it does not replace the remaining classification/provisional-review work.

- Preserve immutable source candidates, account-scoped occurrence identities, optional confirmed stable source IDs, and per-source dispositions. Financial display edits never become matching keys. Deliberately excluded or removed occurrences cannot silently return.
- Confirm actual inclusive download start/end, transaction versus posted-date basis, complete versus partial/incremental coverage, a stable source profile, USD currency, and observation time. Imported time, newest transaction date and confirmed coverage end remain distinct. Row extrema are hints only. Images cannot establish complete coverage.
- Compatible complete snapshots compare per-date multiplicities against the latest accepted snapshot covering that date. Accepted means all posted rows are resolved with reliable keys. Complete sources may contain zero rows. Later accepted observations outrank replayed older files.
- Keys use account, USD, selected source date basis, signed amount and whitespace-normalized raw description, preserving case, punctuation and digits. Profile/layout/date compatibility is required for ID-free count matching. Stable IDs are account-scoped and require explicit mapping confirmation; conflicts require review.
- Equal counts reuse occurrence identities. Count reductions warn and never delete. New occurrences inside prior stable interiors require review; late additions may be eligible only on the prior final posted day or final five transaction days. Unrepresented manual/other-source candidates and changed descriptors remain reviewable.
- Reconcile unchanged rows without writing financial events. Schema 13 adds explicit verified new-row classification/recording in the same import operation. Full auto-post integration must retain these identities and completeness flags.
- Each operation records dependencies on prior accepted decisions. Undo is blocked while later active operations depend on them. Reversing an operation restores its row dispositions/identity aliases atomically alongside existing financial undo.
- QA: three overlapping exports, identical twins, exclusions, manual display edits, stable IDs/conflicts, empty boundaries, late additions, stable-interior anomalies, count reductions, old replays, partial/date-incompatible exports, stale operations, undo dependencies, migration and corrupt recovery.
