# Managed folder backups — section 6

Implemented in release 0.8.0 / schema 43; see [QA](../qa/QA_2026-11-04_managed_backups.md). Implements the selected-folder backup workflow in the approved [extension plan](PAY_HOURS_BACKUP_PLAN.md), using synthetic data and temporary destinations for QA.

## Implementation boundaries

The SQLite working copy stays in local app data. A complete validated SQLite snapshot (including source evidence, payroll and closed reports) becomes an authenticated passphrase-encrypted `.pfbackup` archive. Routine copies never add handoff ancestry or device-switch receipts. The archive has its own bounded, versioned manifest; recovery needs the file and independently retained passphrase, not the local catalog or Windows credential.

Destination setup creates only an owned `Personal Finance Backups/<workspace UUID>/<device UUID>/snapshots` namespace beneath the chosen existing root. A local catalog and matching ownership marker identify exactly which files may be rotated. Path traversal and name-surrogate reparse redirection are refused; cloud placeholder tags that do not redirect names may hydrate through normal file IO. All destructive operations recheck ownership, exact catalog path and content hash. Nothing in another device namespace or an unrecognized file is pruned.

A consistent snapshot is captured under the workspace gate, then encryption, verified local staging and destination copying happen outside that gate. A unique partial file is flushed and hashed before publication by same-directory rename. Success is cataloged only after verification. Backup failure cannot roll back an already saved finance change. A native bounded per-workspace queue debounces writes while the app runs and catches up after launch; no closed-app scheduling or cloud-upload claim.

Default retention keeps 30 distinct daily latest copies, 12 distinct monthly latest copies, the newest validated copy and explicitly protected checkpoints. Every produced archive is decrypted and validated before it becomes eligible to displace an older copy. Restore always authenticates, validates and previews the exact incoming archive, rechecks the local content token, preserves a local branch and performs an atomic SQLite replacement with a retry receipt. Managed settings, provider keys and credentials stay device-local.

Setup requires a backup passphrase and explicit confirmation that it is retained independently. Remembering it in Windows Credential Manager enables automatic runs; manual backup remains available without remembering. Real OneDrive hydration/sync, actual financial data, physical laptop recovery and clean-profile secret recovery remain final-trial checks unless separately evidenced.

## Review map and operating limits

- [Native queue/commands](../../src-tauri/src/backup_commands.rs): a five-second worker checks at most two pending workspace entries; changes debounce for ten seconds with a sixty-second maximum. Import commits, month close and applied handoff expedite a checkpoint. Unchanged snapshots are skipped. Failed attempts retain a visible error; manual retry, a later change or next launch retries the workflow. There is no OS background task after exit.
- [Owned file service](../../src-tauri/src/managed_backups.rs): device-local settings are saved atomically; secrets use a distinct Credential Manager target. An age-encrypted password-check value prevents mixed-password archive sets without requiring cloud hydration of an older archive. New complete archives authenticate and pass recovery validation before rotation. Unknown or interrupted files are never inferred to be owned by extension alone.
- Windows publication uses same-directory `MoveFileExW` without replacement and with write-through. Retention locks the exact archive against concurrent writes/replacement, hashes it, and deletes via that same handle. Managed directory handles prevent ancestor renames while operating; name-surrogate reparse tags are refused. A changed/unavailable old archive stops pruning and retains the new verified copy.
- [Archive/restore](../../src-tauri/src/db/managed_backup.rs): format version 1, schema/workspace/UUID/time/size/hash checks, authenticated SQLite payload, guarded schema, integrity/FK/domain validation and upgrade before activation. The preview token binds both incoming archive and current local contents. An atomic metadata receipt makes a retry return the preserved branch without replaying replacement. Prior `.managed.sqlite` branches are excluded from routine local rotation.
- [UI](../../src/ManagedBackups.tsx): settings, backup status, manual/protected copy, pause, catalog and restore preview. Native folder browsing also has a typed-path fallback. Setup and restore acknowledgements are explicit. Delayed reads cannot cross the active component/workspace lifetime; a successful restore remains shown even if a later page refresh fails.
- The latest daily/monthly copy means the latest available archive in that UTC day/month. A protected checkpoint remains until explicitly unprotected. Limits: 1–365 daily groups, 0–120 monthly groups, 10,000 catalog entries, 256 MB database/258 MB encrypted archive. At the catalog limit, backup stops visibly instead of pruning blindly.

Original monthly archive prose is an implementation goal, not a claim of continuous scheduling on dates when the app was closed. Physical OneDrive, native picker and clean-profile Windows recovery remain unverified; see the QA report and final trial guide.
