# Encrypted desktop/laptop handoff

This section implements an explicit file handoff, not automatic synchronization. Use one computer at a time: export an encrypted snapshot, copy that file, preview/import it on the other PC, then export a new snapshot before returning. The live SQLite database remains in the app's local data directory.

The snapshot contains the database and its embedded original documents, configuration, import provenance and history. API keys/provider settings and per-device appearance stay on each PC. Windows sign-in/device protection continues to protect live data and recovery copies; a separate passphrase protects the portable file.

Use pinned `age` 0.12.1 passphrase encryption, with a fixed scrypt work factor of 18 and a decryption cap of 18. The age implementation performs authenticated encryption; the application must read the complete authenticated stream before parsing/activating it. Inside it, a bounded versioned manifest and SQLite snapshot carry workspace/schema identity and exact database/content hashes. There are no archive paths or executable extraction scripts. Passphrases are not stored. Passphrases require at least 12 characters, no edge whitespace and at most 1,024 UTF-8 bytes. The SQLite snapshot limit is 256 MiB; the encrypted input limit is 258 MiB. Transfer ancestry is limited to 4,096 nodes. Wrong passwords, truncation/tampering, unsupported versions, cross-workspace files and invalid financial provenance must leave current data unchanged.

Each workspace has a lineage ID and immutable transfer ancestry. Compare actual canonical content hashes with a common transfer node; a larger counter is not ancestry. Report unchanged, incoming changes, local changes, divergence or unrelated history. Never silently merge or choose a branch. Every import needs a fresh preview and confirmation; local-ahead/diverged/unrelated replacement needs an additional explicit acknowledgement. Before activation, preserve the old local workspace as a recovery backup excluded from normal rotation. An operation receipt in the candidate database makes a lost response retry return the existing result.

Native work runs off the UI thread. Validate an immutable in-memory candidate and bind the import preview to the archive hash and current local state. Recheck before an atomic SQLite replacement. Active provider requests block handoff; imported requests never restart. An OS-held application lock prevents simultaneous windows on one data directory; per-workspace file leases supplement the command mutex. Output files use generated names and exclusive creation in the managed export folder. Decrypted data is not written to a temporary portable file.

QA uses synthetic stores representing two computers, with separate roots/device IDs. Cover round trips, identical counts with different edits, stale preview/file replacement, replay/rollback, wrong password, corrupted/truncated files, broken financial evidence, unsupported schema, old-schema migration, receipt retries, retained-branch recovery, secrets excluded and atomic failure. Browser tests mock IPC; actual second-device and Windows file-picker/drop checks remain explicit final-trial gaps.

Official references checked November 3, 2026: [age Rust API](https://docs.rs/age/0.12.1/age/), [scrypt recipient](https://docs.rs/age/0.12.1/age/scrypt/struct.Recipient.html), [bounded scrypt identity](https://docs.rs/age/0.12.1/age/scrypt/struct.Identity.html), [age format](https://c2sp.org/age). This is not an independent cryptographic/security audit; the library documents its pre-1.0 status.


SQLite serialization copies WAL format flags even into a memory database. Standalone snapshots normalize file-header bytes 18/19 to rollback format before hashing/encryption, as described in [SQLite's deserialization documentation](https://www.sqlite.org/c3ref/deserialize.html). Potentially malformed input receives the documented 20 spare allocation bytes. Imported triggers and unexpected views are rejected before financial validation or candidate receipt writes.

Local pre-handoff copies end in `.handoff.sqlite` and are intentionally excluded from the ordinary 20-backup rotation. They use Windows/device protection, not the portable passphrase, and continue to occupy local disk until separately managed. Handoff is a complete replacement; equal record counts do not establish equivalence. UI previews classify history and require additional acknowledgement for unrelated, older or diverged copies. Successful writes close the form before refreshing, while failed replies retain the same operation ID.
