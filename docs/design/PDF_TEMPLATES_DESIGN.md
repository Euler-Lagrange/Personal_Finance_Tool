# Local PDF documents and approved templates

Use a pinned local Rust parser with bounded loading/page content, maximum page/text counts, no password handling and no network. Preserve original bytes in the existing evidence store. Cache numbered text pages; legacy evidence-only PDFs can be explicitly extracted. Scans/unsupported encodings stay evidence with a clear manual/optional-AI fallback.

Templates are declarative JSON, never executable code. A user selects bill or card statement, a unique biller identity line, an explicit USD marker, expected page count, exact field labels and inline/next-line placement. Money/date parsing is strict, with a chosen date format. Required bill fields are amount due and due date; required statement fields are statement balance, closing date and due date. Minimum due cannot substitute for statement balance. Optional components support a bounded signed sum check. The sample preview must pass before approval. Approved page/line positions detect later layout drift; reapproval creates an immutable version and never rewrites accepted records.

Review each later document against a selected current template. Retain field page/line/raw evidence and template version. Empty/duplicate labels, identity/currency/page-count/position drift, invalid dates/amounts and arithmetic mismatches block application. A single-value document without components explicitly reports that no arithmetic check is configured.

Applying requires an explicit existing bill occurrence or configured card cycle, a fresh calculation token, reason and confirmation. Bill application changes actual amount/due date and links evidence, preserving the bill plan/payments and paid-capacity checks. Statement application confirms extracted issuer dates/balance and links evidence through the existing statement guards. Show old/new amounts and calculated discrepancy before saving. No operation creates an expense, transfer, payment allocation, or balance checkpoint. Duplicate evidence cannot apply to a different target. Payload-bound receipts, revisions, immutable review evidence and transaction rollback protect retries/history. Reviewed document sources cannot be remapped or re-extracted silently.

QA uses synthetic rendered PDF fixtures and isolated SQLite: extraction limits/malformed/scan/encrypted fallback; exact labels/currency/date/arithmetic/duplicate drift; template approval/versioning; bill/statement application; existing payments and obligations; duplicate observations; stale reviews/failed writes/idempotent retries; old schema and corrupt restore. Browser mocks cover staged-file entry, text evidence, editing/approval, application review, errors/workspace races and compact themes. Actual issuer PDFs and native Windows interactions remain final-trial checks.

Parser reference: https://github.com/J-F-Liu/lopdf (pinned in Cargo.lock; bounded LoadOptions and extract_text_with_limit). Initial templates target supported text labels, not arbitrary transaction-table layouts. Transaction export PDFs and AI-proposed mappings still need their own bounded review path; do not imply full PDF-table support from bill extraction.
