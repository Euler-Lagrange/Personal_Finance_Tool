# Reusing reviewed PDF destinations

After manually applying a bill or statement, the user may explicitly enable reuse for that template version and destination. Store an exact account-specific marker (page plus text, including an identifying digit) confirmed against the applied source. The route points to the stable bill schedule or card account, not a previous month's occurrence. Template revisions require renewed route approval. Paused templates/routes, mismatched account markers, multiple recognized routes, missing fields, layout drift and failed arithmetic remain held.

Automatic application requires configured component arithmetic. A bill's due month selects its active schedule occurrence, generated only for that schedule when needed. A materially shifted due date, cancelled schedule/occurrence or conflicting confirmed actual requires review. A manually overridden due date is preserved unless the document agrees with that override. Statement cutoff selects the cycle; automatic confirmation requires a complete calculation equal to the issuer total, and never overwrites conflicting confirmed issuer values. Existing paid capacity, obligation/date locks, evidence uniqueness and closed-report invariants remain authoritative.

Automatic application uses the same preview/token/write path as manual review inside an isolated savepoint. A rejected update leaves the PDF and any staged table rows available and records a visible held reason. It creates no spending/payment. One PDF may supply both rows and statement evidence: account mapping may be confirmed for the same locked account, while raw source text remains immutable. Routing settings have revision checks, payload-bound receipts, application provenance and restore validation.
